# Actividad 16 — Comparar configuración antes y después
| Control | Estado Inicial | Estado Final | Justificación técnica |
| :--- | :--- | :--- | :--- |
| **listen_addresses** | Configurado con asterisco (`*`), aceptando peticiones en todas las interfaces de red disponibles. | Restringido exclusivamente a `localhost`. | Disminuye de forma drástica la superficie de exposición al limitar el servicio únicamente al entorno local. |
| **pg_hba.conf** | Contenía directivas genéricas de tipo `all all` con alcances demasiado amplios. | Sustituido por tuplas precisas, por ejemplo: `host pruebas_DBA 127.0.0.1/32 y ::1/128`. | Aplica el principio de especificidad: combina base de datos, usuario, origen exacto y método criptográfico. |
| **Método de autenticación** | Basado en el estándar seguro `scram-sha-256`. | Consolidado en `scram-sha-256` (sin modificaciones). | Representa el mecanismo nativo más robusto para la validación de credenciales basadas en contraseña. |
| **Usuarios administrativos** | El rol `postgres` era el único habilitado con privilegios de inicio de sesión y superusuario. | El uso de `postgres` se limita estrictamente a tareas de mantenimiento local. | Las cuentas con privilegios globales no deben reutilizarse en la operación cotidiana de las aplicaciones. |
| **Cuentas de aplicación** | Inexistentes en el ejercicio inicial (se operaba directamente con el superusuario). | Sin cambios adicionales aplicados en este entorno de prácticas. | Se mantiene el rigor del mínimo privilegio; en un escenario real se diseñan roles específicos para el software. |
| **Puerto de escucha** | 5432 abierto y accesible mediante interfaces genéricas (`0.0.0.0` y `[::]`). | 5432 operativo, acotado de forma exclusiva a bucle local (`127.0.0.1` y `[::1]`). | Aunque el puerto no cambia, se neutraliza la accesibilidad directa desde las interfaces públicas de red. |
| **Cifrado en tránsito (TLS)** | Desactivado (`ssl = off`), operando con canales de comunicación sin cifrar. | Entorno local sin cambios; para producción se establece `ssl = on` y directivas tipo `hostssl`. | El tráfico local no abandona la máquina física; sin embargo, en topologías remotas el uso de TLS es obligatorio. |
| **Permisos a nivel de SO** | Inspeccionados mediante comandos como `icacls` en entornos Windows para suprimir accesos a usuarios generales o invitados. | Sin modificaciones adicionales en los archivos del sistema operativo local. | Las restricciones internas con `GRANT`/`REVOKE` son insuficientes si los ficheros de configuración carecen de protección en el sistema operativo. |
| **Extensiones del motor** | Únicamente se encontraba activa la extensión base `plpgsql 1.0`. | Mantenimiento de `plpgsql 1.0` sin adiciones innecesarias. | Se evita la proliferación de funcionalidades accesorias que amplíen innecesariamente los riesgos del motor. |
| **Gestión de conexiones** | Valores por defecto (`max_connections = 100`, timeouts deshabilitados con valor `0`). | Propuesta de ajuste operativo implementando límites de tiempo (por ejemplo, 30s de límite de sentencia y 60s en transacciones inactivas). | Previene el bloqueo de recursos ante consultas colgadas o conexiones de cliente abandonadas en estado inactivo. |
